4.2 Handling Existing Feature Branches
Problem: Developers have active feature branches with old versioning.
Solution: Dual-Support Period (2-4 weeks)
Option A: Force Rebase (Recommended if team is small)
bash# Developer workflow
git checkout feature/my-feature
git fetch origin
git rebase origin/main

# Resolve any POM conflicts by accepting main's CI-friendly version
# Test locally
mvn clean install

git push -f origin feature/my-feature
Option B: Gradual Migration (For larger teams)
Support both old and new versioning temporarily:
xml<!-- BOM temporary compatibility -->
<properties>
    <revision>0.0.1</revision>
    <changelist>-SNAPSHOT</changelist>
    
    <!-- Legacy support - remove after transition -->
    <code-style.version>${code-style.legacy.version}</code-style.version>
    <code-style.legacy.version>0.0.1-user.nameX</code-style.legacy.version>
</properties>
Update CI/CD to handle both:
yaml.maven-install:
  script:
    - |
      # Check if POM uses CI-friendly versions
      if grep -q '\${revision}\${changelist}' pom.xml; then
        echo "Using CI-friendly versions"
        mvn install -Drevision=0.0.1 -Dchangelist="${CHANGELIST}"
      else
        echo "Using legacy versioning (deprecated)"
        mvn install
      fi
